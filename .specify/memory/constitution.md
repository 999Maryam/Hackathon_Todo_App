## Core Principles

### I. Spec-Driven Development (SDD)

Every line of code MUST be generated by Claude Code + Spec-Kit Plus from refined specifications. The mandatory workflow is:

```
/specify → /plan → /tasks → /implement
```

**No manual coding allowed.** Specifications MUST include:
- Clear acceptance criteria
- User stories with priorities
- Success conditions
- Testable outcomes

This ensures alignment with requirements, enables independent verification of completion, and provides full traceability from requirement to implementation.

### II. Progressive Evolution

Each phase MUST build directly on the previous one without breaking compatibility:

| Phase | Builds On | Delivers |
|-------|-----------|----------|
| I | — | Console CRUD (in-memory) |
| II | Phase I logic | Multi-user web app + JWT auth + Neon persistence |
| III | Phase II DB + auth + API | AI chatbot with MCP tools |
| IV | Phase III app | Dockerized, Helm-deployed on Minikube |
| V | Phase IV containers | Event-driven architecture with Kafka/Dapr |

Backward compatibility MUST be maintained. Breaking changes require explicit migration paths.

### III. Reusable Intelligence

Maximize agent skills, sub-agents, and reusable patterns across phases. This is a bonus priority:

- Reusable agents/skills: +200 bonus points
- Cloud blueprints: +200 bonus points
- Total reusability bonus: +400 points

All agent patterns MUST be documented for reuse. Cloud deployment templates MUST be parameterized for multi-environment use.

### IV. Security First

JWT-based stateless authentication (Better Auth) with strict user isolation:

**Authentication Requirements:**
- Better Auth with JWT plugin enabled
- Shared `BETTER_AUTH_SECRET` environment variable
- Token expiry configured (recommended: 7 days)
- No session storage in database - JWT only

**Authorization Requirements:**
- Every API request MUST include valid JWT in `Authorization: Bearer <token>` header
- All routes MUST extract `current_user` via reusable dependency/middleware
- 401 Unauthorized for missing or invalid tokens
- 403 Forbidden for cross-user access attempts

**Data Isolation:**
- Every database record MUST include `user_id` foreign key
- Query-level filtering enforced: `WHERE user_id = current_user.id`
- No user can access, modify, or delete another user's data

### V. Stateless & Resilient Design

No in-memory state. Persist everything in Neon PostgreSQL:

**Core Tables:**
- `tasks` (user_id FK)
- `conversations` (user_id FK) — Phase III+
- `messages` (user_id FK, conversation_id FK) — Phase III+

**Phase V Extended Tables:**
- `tags` (id, name, user_id FK) — User-defined tags
- `task_tags` (task_id FK, tag_id FK) — Many-to-many relationship
- `reminders` (id, task_id FK, remind_at, sent) — Scheduled reminders
- `recurring_configs` (id, task_id FK, frequency, next_occurrence) — Recurring task settings
- `audit_logs` (id, task_id, event_type, user_id, timestamp, data) — Event history

**Phase V Task Table Extensions:**
```sql
ALTER TABLE tasks ADD COLUMN priority VARCHAR(10) DEFAULT 'medium';  -- high, medium, low
ALTER TABLE tasks ADD COLUMN due_date TIMESTAMP;
ALTER TABLE tasks ADD COLUMN is_recurring BOOLEAN DEFAULT FALSE;
ALTER TABLE tasks ADD COLUMN recurring_config_id INTEGER REFERENCES recurring_configs(id);
```

**Resilience Requirements:**
- Application MUST survive restarts without data loss
- Concurrent user access MUST be supported
- Migrations via Alembic or SQLModel metadata
- Foreign key constraints and proper indexing enforced

### VI. Cloud-Native Mindset

Container-first, orchestration-ready design:

**Phase IV:**
- Docker containerization (frontend + backend)
- Helm charts for Kubernetes deployment
- Minikube local orchestration
- kubectl-ai / kagent usage demonstrated

**Phase V:**
- Production cloud deployment (DOKS/AKS/GKE)
- CI/CD via GitHub Actions
- Monitoring and logging infrastructure

### VII. AI-Native Focus (Phase III+)

Natural language understanding with tool-chaining via MCP:

**MCP Tools (exactly as specified):**
- `add_task` — Create a new task
- `list_tasks` — List all user tasks
- `complete_task` — Mark task as complete
- `delete_task` — Remove a task
- `update_task` — Modify task properties

**Behavior Requirements:**
- Confirmation before destructive operations
- Graceful error handling with user-friendly messages
- Conversation persistence in database
- Stateless server design (no in-memory conversation state)

**Bonus Features:**
- Urdu language support: +100 bonus points
- Voice input commands: +200 bonus points

### VIII. Maintainability & Traceability

Every file MUST contain comments linking to Task ID + spec section:

{
  "task_id": 123,

## Phase V: Dapr Building Blocks

### Required Dapr Components

| Building Block | Component Type | Purpose |
|----------------|----------------|---------|
| **Pub/Sub** | `pubsub.kafka` | Kafka abstraction - no Kafka library needed |
| **State Management** | `state.postgresql` | Conversation state, task cache |
| **Service Invocation** | Built-in | Frontend ↔ Backend with retries, mTLS |
| **Bindings (Cron)** | `bindings.cron` | Scheduled reminder checks |
| **Secrets** | `secretstores.kubernetes` | API keys, DB credentials |

### Dapr Benefits

| Without Dapr | With Dapr |
|--------------|-----------|
| Import Kafka, Redis, Postgres libraries | Single HTTP API for all |
| Connection strings in code | Dapr components (YAML config) |
| Manual retry logic | Built-in retries, circuit breakers |
| Service URLs hardcoded | Automatic service discovery |
| Secrets in env vars | Secure secret store integration |
| Vendor lock-in | Swap Kafka for RabbitMQ with config change |

### Dapr Component Examples

**Pub/Sub (Kafka):**
```yaml
apiVersion: dapr.io/v1alpha1
kind: Component
metadata:
  name: kafka-pubsub
spec:
  type: pubsub.kafka
  version: v1
  metadata:
    - name: brokers
      value: "redpanda:9092"
```

**Cron Binding (Reminders):**
```yaml
apiVersion: dapr.io/v1alpha1
kind: Component
metadata:
  name: reminder-cron
spec:
  type: bindings.cron
  version: v1
  metadata:
    - name: schedule
      value: "*/5 * * * *"  # Every 5 minutes
```
