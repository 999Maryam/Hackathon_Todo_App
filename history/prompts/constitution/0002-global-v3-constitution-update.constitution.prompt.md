- Cloud-Native Mindset: Container-first (Docker), orchestration-ready (Kubernetes/Minikube → DOKS/AKS/GKE), event-driven (Kafka + Dapr in Phase V).

- Maintainability & Traceability: Every file must contain comments linking to Task ID + spec section. All specs organized in /specs/ (features/api/database/ui).

- Tech Stack (locked – no deviations):
  Phase I–II:   Python 3.13+, FastAPI, SQLModel, Neon PostgreSQL, Next.js 16+ App Router, Better Auth (JWT)
  Phase III:    OpenAI Agents SDK, Official MCP SDK, OpenAI ChatKit
  Phase IV–V:   Docker, Minikube, Helm, kubectl-ai / kagent, Kafka (or Redpanda), Dapr (Pub/Sub, State, Jobs, Secrets, Service Invocation)
- Code Quality:
  - Python: PEP 8, type hints, Pydantic/SQLModel validation
  - TypeScript/Next.js: ESLint + Prettier, Tailwind CSS
  - Testing: pytest (backend), Jest/component tests (frontend), end-to-end flows; aim >80% coverage
- API & Tools:
  - RESTful endpoints (Phase II) → single stateless /api/{user_id}/chat (Phase III+)

  - Event topics (Phase V): task-events, reminders, task-updates
- Authentication & Authorization:

  - All endpoints protected; extract current_user via reusable dependency/middleware
  - Ownership enforced at DB query level (WHERE user_id = current_user.id)
- Database:
  - Core tables: tasks, conversations, messages (user_id FK everywhere)
  - Migrations via Alembic or SQLModel metadata
- Documentation:
  - Root + frontend/backend CLAUDE.md files
  - /specs/ folder with constitution, specify, plan, api, database, ui subfolders
  - README.md with env vars, setup per phase, docker-compose / helm instructions

- Phases must be sequential: Phase III reuses Phase II DB + auth + API base
